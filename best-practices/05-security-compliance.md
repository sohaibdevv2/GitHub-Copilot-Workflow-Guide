# Security & Compliance with GitHub Copilot

## Security Considerations

### Principle 1: Never Commit Secrets

**Absolute Rule**: Never paste credentials, API keys, or passwords to Copilot

```javascript
// ❌ NEVER DO THIS
function connectDB() {
  const password = "super_secret_password_123";
  // Copilot sees this!
}

// ✅ ALWAYS DO THIS
function connectDB() {
  const password = process.env.DB_PASSWORD;
  // Environment variable, never exposed
}
```

### Use .copilotignore

Create in project root:

```
# Critical files
.env
.env.local
.env.*.local
secrets/
*.key
*.pem
config/prod.js
private/

# Generated by build tools
dist/
build/
node_modules/
```

### Configure Git Hooks

Create `.husky/pre-commit`:

```bash
#!/bin/sh
. "$(dirname "$0")/_/husky.sh"

# Check for secrets before commit
echo "Checking for secrets..."
git-secrets --pre_commit

# Prevent .env files
if git diff --cached --name-only | grep -q "\.env"; then
  echo "ERROR: .env file staged for commit!"
  exit 1
fi

npm run lint
npm test
```

## Code Security Patterns

### Secure Validation

```typescript
// ✓ GOOD - Proper validation
function validateUserInput(input: string): boolean {
  if (!input || typeof input !== 'string') return false;
  if (input.length > 255) return false;
  if (!/^[a-zA-Z0-9_-]+$/.test(input)) return false;
  return true;
}

// ❌ POOR - No validation
function processInput(input) {
  return input.toUpperCase();
}
```

### Secure Authentication

```javascript
// ✓ GOOD - Use established library
import jwt from 'jsonwebtoken';

function generateToken(userId) {
  return jwt.sign(
    { userId },
    process.env.JWT_SECRET,
    { expiresIn: '24h' }
  );
}

// ❌ POOR - Custom crypto (don't do this!)
function generateToken(userId) {
  return Buffer.from(userId).toString('base64');  // ❌ Not secure!
}
```

### Secure Data Handling

```javascript
// ✓ GOOD - Hash passwords
import bcrypt from 'bcrypt';

async function storePassword(password) {
  const hashed = await bcrypt.hash(password, 10);
  return hashed;  // Store hashed, never plain text
}

// ❌ POOR - Store plaintext
function storePassword(password) {
  return password;  // ❌ NEVER store plaintext!
}
```

## Review Process for Sensitive Code

### High-Risk Code

Require expert review for:
- Authentication logic
- Authorization/permissions
- Cryptography
- Payment processing
- Data encryption
- Password handling
- API authentication

### Review Workflow

```markdown

3. Developer tags PR with "security-review"
4. Security team reviews
5. Changes approved
```


## Compliance Automation

### Automated Security Checks

```yaml
# .github/workflows/security.yml

name: Security Checks

on: [pull_request]

jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v2
      
      - name: Run secret scanner
        run: |
          npm install -g git-secrets
          git-secrets --register-aws-provider
          git-secrets --scan
      
      - name: SAST analysis
        run: npm run sast
      
      - name: Dependency audit
        run: npm audit --audit-level=moderate
      
      - name: Code quality scan
        run: npm run sonar
```

## Incident Response

### If Secrets Exposed

```markdown
# Incident Response Checklist

1. STOP using Copilot immediately
2. Rotate exposed credentials
3. Scan git history for other exposures
4. Notify security team
5. Document incident
6. Conduct post-mortem
7. Implement preventive controls
8. Resume with enhanced security
```

### Command to Find Exposed Secrets

```bash
# Search git history for secrets
git-secrets --scan

# Find specific patterns
git log --all -p | grep -i "password\|secret\|api_key"

# Rotate credentials
npm run rotate-secrets
```
